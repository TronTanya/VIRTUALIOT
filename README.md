# VirtualIoT — виртуальная лаборатория умного помещения

Учебное приложение для студенческой научной конференции. Оно моделирует одно помещение с
виртуальными датчиками (температура, влажность, освещённость) и устройствами (обогреватель,
вентиляция, лампа). Пользователь настраивает правила автоматизации с гистерезисом и наблюдает,
как они влияют на смоделированную среду.

> **Все показания смоделированы.** Приложение не подключено к реальному оборудованию и не
> предсказывает поведение реального здания.

## Установка и запуск

Требуется Python 3.11 или новее. Платные API, облачные аккаунты и оборудование не нужны.

### Windows (PowerShell или cmd)

```bat
cd VirtualIoT
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Если PowerShell запрещает запуск скрипта активации, выполните один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или используйте `cmd`.

### macOS / Linux

```bash
cd VirtualIoT
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется в браузере по адресу http://localhost:8501.

### Тесты

```bash
python -m pytest -q
```

## Порядок шага моделирования

Шаг фиксирован: Δt = 1 мин. Длительность — 10…1440 мин. Наблюдения выполняются в моменты
t = 0, 1, …, N, поэтому результат содержит N + 1 строк:

1. Получить показания датчиков в момент t.
2. Применить правила автоматизации.
3. Задать воздействие устройств на интервале [t; t+1).
4. Продвинуть состояние среды к моменту t + 1.
5. Записать результат.

Строка t = 0 — «Начальное наблюдение» (до начала прогона все устройства выключены). Строки
t < N содержат состояния устройств на интервале [t; t+1). Строка t = N — «Конечное наблюдение»
без следующего интервала, поэтому состояния устройств в ней пусты. Время работы устройства
считается только по N интервалам и не может превысить длительность моделирования.

## Модель

Обозначения: q, v, l ∈ {0, 1} — состояния обогревателя, вентиляции и лампы на интервале.

### Температура, °C

```
T[t+1] = T[t] + (k_T + k_TV · v[t]) · (T_out − T[t]) + h · q[t]
```

| Коэффициент | Смысл | Единицы | По умолчанию |
|---|---|---|---|
| k_T | обмен теплом с улицей | 1/мин | 0,01 |
| k_TV | добавка к обмену при вентиляции | 1/мин | 0,03 |
| h | нагрев обогревателем | °C/мин | 0,4 |

### Относительная влажность, %

```
H[t+1] = H[t] + (k_H + k_HV · v[t]) · (H_out − H[t])
```

| Коэффициент | Смысл | Единицы | По умолчанию |
|---|---|---|---|
| k_H | обмен влагой с улицей | 1/мин | 0,005 |
| k_HV | добавка к обмену при вентиляции | 1/мин | 0,05 |

Это **учебное приближение**: не моделируются абсолютная влажность, конденсация и зависимость
относительной влажности от температуры.

**Устойчивость.** Проверяются условия 0 < k_T < 1, 0 < k_H < 1, k_T + k_TV ≤ 1, k_H + k_HV ≤ 1.
При их выполнении шаг релаксации не перескакивает через уличное значение из-за неверных настроек.

### Освещённость, лк

```
E_nat[t] = E_0 · (1 + a · sin(2π · t / P))     — естественный свет
E[t]     = E_nat[t] + L · l[t−1]               — общая освещённость помещения
```

E_0 — средний естественный свет, a — амплитуда колебаний (0…100 %), P — период (по умолчанию
120 мин), L — вклад лампы (по умолчанию 400 лк). В момент наблюдения t лампа светит в состоянии,
выбранном на предыдущем интервале.

### Датчики и шум

```
показание[t] = состояние[t] + σ · z[t]
```

z[t] — стандартный нормальный шум. Для каждого из четырёх датчиков (температура, влажность,
общая освещённость, естественный свет) создаётся независимый воспроизводимый поток
(`numpy.random.SeedSequence(seed).spawn(4)`). СКО по умолчанию: 0,1 °C; 0,5 %; 5 лк.

- Шум влияет только на показания, но не на состояние среды.
- Измеренная влажность ограничивается диапазоном 0…100 %, освещённость — неотрицательными значениями.
- В парных сравнениях одни и те же последовательности шума генерируются заранее и передаются в оба прогона.

## Автоматизация с гистерезисом

| Устройство | Включается | Выключается | Датчик |
|---|---|---|---|
| Обогреватель | T < нижнего порога | T > верхнего порога | температура |
| Вентиляция | H > верхнего порога | H < нижнего порога | влажность |
| Лампа | E_nat < нижнего порога | E_nat > верхнего порога | естественный свет |

Между порогами устройство сохраняет текущее состояние. Сравнения строгие: значение, **в точности
равное порогу**, считается внутри полосы и не меняет состояние. Нижний порог должен быть строго
меньше верхнего.

**Почему у лампы отдельный датчик.** Если бы лампа управлялась по общей освещённости, то после
включения её собственный свет поднял бы показание выше верхнего порога, лампа выключилась бы, свет
упал бы — и цикл повторялся бы. Поэтому контроллер использует датчик естественного света, который не
учитывает вклад лампы, а общая освещённость помещения показывается отдельно и используется для
оценки целевого диапазона.

При выключенной автоматизации пользователь задаёт фиксированные ручные состояния устройств на весь
прогон.

## Показатели

- **Время работы** — число минутных интервалов, на которых устройство включено.
- **Переключения** — число изменений состояния относительно предыдущего (до старта все выключены).
- **Время в целевом диапазоне** — доля показаний датчиков (все N + 1 наблюдений, границы включены).
- **Электроэнергия (оценка)** при постоянной номинальной мощности:

```
energy_kWh = power_W × enabled_minutes / 60 / 1000
```

Мощности по умолчанию: обогреватель 1500 Вт, вентиляция 40 Вт, лампа 60 Вт. Это оценка при
фиксированных допущениях, а не прогноз счёта и не доказательство экономии.

## Пресеты

Пресеты содержат только параметры модели; результаты вычисляются при запуске.

- **Холодное помещение** — 15 °C в помещении, −5 °C на улице, пороги обогревателя 20/22 °C.
- **Высокая влажность** — 80 % в помещении, 40 % на улице, пороги вентиляции 50/60 %.
- **Недостаточное освещение** — естественный свет 260 лк ±50 % с периодом 120 мин, пороги лампы 250/350 лк.

## Сравнение сценариев

На вкладке «Сценарии» текущие параметры запускаются дважды: «Автоматизация выключена» (все
устройства выключены) и «Автоматизация включена». Оба прогона используют одинаковые начальные
условия, длительность, коэффициенты и последовательности шума. Сравниваются время в целевых
диапазонах, время работы, число переключений и оценка электроэнергии. Улучшение условий может
требовать дополнительной электроэнергии, поэтому автоматизация не описывается как энергосберегающая.

## Экспорт

- Показания и состояния устройств — CSV (UTF-8 с BOM, открывается в Excel).
- Журнал событий — CSV (UTF-8 с BOM).
- Конфигурация — JSON (версия модели, шаг, все параметры, зерно).
- Автономный HTML-отчёт: параметры, зерно, версия модели, шаг, рассчитанные показатели,
  журнал событий, сравнение (если выполнено для тех же параметров) и допущения модели.
  Все значения в отчёте экранируются.
- Таблица сравнения и результаты эксперимента с гистерезисом — CSV.

Данные моделирования не сохраняются автоматически: они существуют только в сессии браузера,
пока пользователь сам их не скачает. При изменении параметров прежние результаты помечаются как
требующие пересчёта.

## Исследование

**Гипотеза:** «Виртуальная модель позволяет исследовать влияние пороговых правил и гистерезиса на
условия в помещении и частоту переключения устройств.»

**Воспроизводимый эксперимент** (вкладка «Сценарии», раздел «Эксперимент»):

1. Загрузите пресет «Холодное помещение» — начальные условия и зерно шума фиксированы.
2. Выберите «Обогреватель», центр 21 °C, узкая полоса 0,4 °C, широкая 3 °C.
3. Нажмите «Провести эксперимент»: оба прогона используют один и тот же шум.
4. Сравните число переключений и долю времени в целевом диапазоне, скачайте CSV.
5. Интерпретируйте компромисс: узкая полоса держит температуру ближе к центру, но при шуме
   датчика вызывает больше переключений; широкая полоса уменьшает переключения, но допускает
   большие колебания. Какой вариант предпочтительнее, зависит от целевого диапазона и параметров
   устройства — широкая полоса не всегда лучше.

В проекте нет данных реальных датчиков, опросов или участников, и он не заявляет об экономии энергии.

## Демонстрация за три минуты

1. **(0:00)** Вкладка «Умное помещение» → пресет «Холодное помещение» → «Загрузить пресет».
2. **(0:30)** Выключите переключатель «Автоматизация включена» (все устройства выключены) →
   «Запустить симуляцию». Температура падает к уличной, время в целевом диапазоне — 0 %.
3. **(1:00)** Включите автоматизацию: появится предупреждение о необходимости пересчёта →
   «Запустить симуляцию».
4. **(1:20)** Покажите график температуры с порогами 20/22 °C, график состояний обогревателя
   и журнал событий: каждое переключение объяснено показанием и порогом.
5. **(2:00)** Вкладка «Сценарии» → «Сравнить сценарии»: время в диапазоне выросло, но обогреватель
   израсходовал дополнительную электроэнергию (оценка).
6. **(2:40)** Вернитесь на первую вкладку → «Отчёт (HTML)».

## Ограничения

- Модель учебная, коэффициенты постоянные и не откалиброваны по реальному зданию.
- Не учитываются люди, солнечный нагрев, теплоёмкость стен, задержки и инерция устройств.
- Влажность — упрощённая релаксационная модель относительной влажности.
- Естественный свет — детерминированная синусоида, а не реальные погодные данные.
- Мощность устройств постоянна; энергия — оценка, а не прогноз счёта.
- Моделируется одно помещение.
